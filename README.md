# NMH Кинобюро

**NMH Кинобюро** — веб-платформа для взаимодействия независимых кинематографистов, продюсеров и команды News Media Holding. Сервис использует AI для анализа кинопроектов и подбора историй под запросы продюсеров.

## 1. Технологический стек

| Компонент | Технология | Назначение |
|---|---|---|
| Интерфейс | Python, Streamlit | Веб-приложение и пользовательские сценарии |
| AI | GigaChat-2 API | Анализ проектов и интеллектуальный подбор |
| База данных | Firebase Firestore | Хранение проектов, заявок и избранного |
| Работа с файлами | pypdf, python-docx | Извлечение текста из PDF и DOCX |
| Развёртывание | Streamlit Community Cloud | Публикация приложения |

## 2. Архитектура проекта

Приложение разделено на пользовательский интерфейс, AI-модуль, модуль работы с данными и обработчик файлов.

```text
nmh-kinoburo/
│
├── app.py                 # Интерфейс и логика страниц
├── backend/
│   ├── ai.py              # Анализ и AI-поиск проектов
│   ├── db.py              # Работа с Firebase Firestore
│   └── files.py           # Проверка и обработка файлов
│
├── requirements.txt       # Зависимости проекта
└── README.md              # Документация
```

**Основные модули:**

- `app.py` — формы подачи проектов, поиск, заявки на продвижение и панель команды NMH.
- `backend/ai.py` — взаимодействие с GigaChat-2, формирование запросов, разбор и проверка AI-ответов.
- `backend/db.py` — сохранение и получение данных из Firestore.
- `backend/files.py` — проверка загружаемых файлов и извлечение текста.

Такое разделение позволяет изменять AI-логику, интерфейс и работу с базой независимо друг от друга.

## 3. Использование искусственного интеллекта

В проекте реализованы два AI-сценария на базе **GigaChat-2**.

**Анализ кинопроекта**

После подачи заявки AI анализирует описание проекта и формирует структурированный результат:

- краткое содержание;
- жанры и оценку жанра, выбранного автором;
- аргументы в пользу жанровой классификации;
- темы, сильные стороны и риски;
- предполагаемую аудиторию;
- рекомендации по развитию проекта.

Выбранный автором жанр передаётся в запрос отдельно. AI должен оценить его самостоятельно, а не автоматически соглашаться с автором.

**Интеллектуальный поиск для продюсеров**

Продюсер описывает задачу, желаемые жанры и темы. AI сопоставляет запрос со всеми проектами в базе, учитывая содержание, жанр, аудиторию, формат и стадию производства.

Результат включает:
- оценку соответствия от 0 до 100;
- объяснение, почему проект подходит;
- возможные ограничения и недостаток информации;
- ранжированный список проектов.

Поиск основан на смысловом анализе GigaChat, а не только на совпадении ключевых слов.

**Контроль AI-ответов**

AI получает инструкции возвращать результат в формате JSON. Приложение проверяет структуру ответа, наличие обязательных полей и корректность списка найденных проектов. Если AI возвращает некорректный результат, приложение сообщает об ошибке, а не использует непроверенные данные как успешный ответ.

## 4. Хранение и обработка данных

Для хранения информации используется **Firebase Firestore**.

Основные коллекции:

| Коллекция | Содержимое |
|---|---|
| `projects` | Проекты режиссёров, контакты и результаты AI-анализа |
| `campaigns` | Заявки на продвижение фильмов |
| `saved_projects` | Сохранённые продюсерами проекты |

Данные записываются в облачную базу и загружаются при обращении к соответствующим разделам приложения. Для документов используются уникальные идентификаторы Firestore.

**Обработка файлов**

Поддерживаются форматы PDF, DOCX и TXT. Максимальный размер файла — 15 МБ. Перед обработкой проверяются расширение, наличие содержимого и размер. Извлечённый текст может быть добавлен к описанию проекта для AI-анализа.

## 5. Надёжность и безопасность

В прототипе предусмотрены следующие механизмы:

- API-ключ GigaChat и параметры подключения Firebase хранятся в Secrets, а не в исходном коде.
- При отсутствии AI-ключа приложение может сохранить проект без AI-анализа.
- Ошибки AI-запросов и обработки файлов перехватываются и отображаются пользователю.
- Перед сохранением проверяются обязательные поля формы.
- Для AI-поиска проверяется полнота списка результатов: каждый переданный проект должен присутствовать в ответе ровно один раз.
- Загружаемые файлы ограничены разрешёнными форматами и размером.

**Ограничения текущего прототипа:** пользовательская аутентификация и разграничение прав доступа пока не реализованы. Перед промышленным использованием необходимо добавить авторизацию, правила доступа Firestore, защиту персональных данных и дополнительные ограничения на обработку запросов.

## 6. Запуск проекта

**1. Клонирование репозитория**

```bash
git clone https://github.com/DaRvinU/nmh-kinoburo.git
cd nmh-kinoburo
```

**2. Установка зависимостей**

```bash
pip install -r requirements.txt
```

**3. Настройка секретов**

Для локального запуска создайте файл `.streamlit/secrets.toml`:

```toml
GIGACHAT_CREDENTIALS = "ваши_учётные_данные_GigaChat"

[firebase]
# Здесь указываются поля сервисного аккаунта Firebase
```

В блок `[firebase]` необходимо добавить данные сервисного аккаунта Firebase. Файл с секретами нельзя публиковать в GitHub.

**4. Запуск приложения**

```bash
streamlit run app.py
```
