# NMH Кинобюро

**NMH Кинобюро** — веб-платформа для взаимодействия независимых кинематографистов, продюсеров и команды News Media Holding. Сервис использует AI для анализа кинопроектов и подбора историй под запросы продюсеров.

Ссылка на деплой приложения: https://nmh-kinoburo-pobedavictoryplsplsplspls.streamlit.app/

## 1. Технологический стек

| Компонент | Технология | Назначение |
|---|---|---|
| Интерфейс | Python, Streamlit | Веб-приложение и пользовательские сценарии |
| AI | GigaChat-2 API | Анализ проектов и интеллектуальный подбор |
| База данных | Firebase Firestore | Хранение проектов, заявок и избранного |
| Работа с файлами | pypdf, python-docx | Извлечение текста из PDF и DOCX |
| Тесты и CI | pytest, GitHub Actions | Автоматическая проверка при каждом коммите |
| Развёртывание | Streamlit Community Cloud | Публикация приложения |

## 2. Архитектура проекта

```text
nmh-kinoburo/
├── app.py                  # Интерфейс Streamlit и логика страниц
├── backend/
│   ├── ai.py               # GigaChat: анализ проекта и ранжирование (основной AI-модуль)
│   ├── matching.py         # Поиск по словам (TF-IDF): используется только как baseline в оценке качества
│   ├── db.py               # Firebase Firestore
│   └── files.py            # Проверка и чтение PDF/DOCX/TXT
├── eval/                   # Оценка качества ИИ-подбора: данные, запросы, скрипт, результаты
├── tests/                  # Автотесты (запускаются в GitHub Actions)
├── .github/workflows/      # tests.yml — тесты, eval.yml — ручной запуск оценки качества
└── requirements.txt
```

**Поток данных**

```text
Режиссёр → форма (app.py) → files.py (текст из PDF/DOCX) → ai.analyze_project (GigaChat-2)
        → db.save_project → Firestore (projects)

Продюсер → запрос → db.get_projects → ai.rank_projects_ai (GigaChat-2, ответ в JSON)
        → проверка полноты ответа → фильтр по порогу MIN_SCORE = 40
        → список проектов или сообщение «подходящих проектов не найдено»
```

**Основные модули**

- `app.py` — формы подачи проектов, поиск, заявки на продвижение и панель команды NMH (закрыта паролем).
- `backend/ai.py` — взаимодействие с GigaChat-2, формирование запросов, разбор и проверка AI-ответов, фильтр по порогу релевантности.
- `backend/db.py` — сохранение и получение данных из Firestore.
- `backend/files.py` — проверка загружаемых файлов и извлечение текста.
- `backend/matching.py` — классический поиск по словам (TF-IDF). В приложении не используется, нужен для сравнения с ИИ-подбором.

## 3. Использование искусственного интеллекта

В проекте реализованы два AI-сценария на базе **GigaChat-2**. Готовая модель используется через API, собственное обучение не проводилось.

**Анализ кинопроекта.** После подачи заявки AI анализирует описание и формирует структурированный результат: краткое содержание, жанры и оценку жанра, выбранного автором, аргументы в пользу классификации, темы, сильные стороны и риски, аудиторию, рекомендации. Выбранный автором жанр передаётся отдельно, AI оценивает его самостоятельно и не должен соглашаться автоматически. Температура 0.2 — для стабильности результата.

**Интеллектуальный поиск для продюсеров.** Продюсер описывает задачу, жанры и темы. AI сопоставляет запрос со всеми проектами в базе, учитывая содержание, жанр, аудиторию, формат и стадию. Результат: оценка соответствия 0–100, объяснение, ограничения и недостаток данных, ранжированный список. Температура 0.1.

Поиск основан на смысловом анализе, а не на совпадении слов: запрос о «взрослении» должен находить проект о «поиске себя», даже если слова «взросление» в нём нет.

**Если подходящих проектов нет.** Проекты с оценкой ниже порога `MIN_SCORE = 40` не показываются. Если ни один проект не прошёл порог, приложение сообщает об этом и показывает лучшую найденную оценку, вместо того чтобы выдавать случайные совпадения.

**Контроль AI-ответов**

- AI должен вернуть JSON; приложение проверяет структуру и обязательные поля.
- Для поиска проверяется полнота списка: каждый переданный проект присутствует в ответе ровно один раз, выдуманные проекты отклоняются.
- Оценка ограничивается диапазоном 0–100.
- При некорректном ответе приложение показывает ошибку и не использует непроверенные данные.
- Тексты проектов передаются в промпт как данные, с явной инструкцией не выполнять команды из них.

## 4. Оценка качества ИИ-подбора

Качество проверено на тестовом наборе: 10 вымышленных проектов и 25 запросов (20 с ожидаемым подходящим проектом, 5 без подходящих). ИИ-подбор сравнивается с обычным поиском по словам (TF-IDF) на тех же запросах.

Актуальные результаты и разбор по каждому запросу: [`eval/results.md`](eval/results.md).

Метрики:

- **Релевантность Топ-3** — доля запросов, в которых хотя бы один подходящий проект попал в показанные (до трёх).
- **Precision@3** — доля подходящих проектов среди показанных (до трёх). Считается от числа показанных, потому что у большинства тестовых запросов один подходящий проект.
- **Корректный ответ «ничего не подошло»** — доля запросов без подходящих проектов, на которые система ничего не показала.

Данные и скрипт лежат в папке `eval/`. Запуск: `python eval/run_eval.py` (нужен `GIGACHAT_CREDENTIALS`) или вручную через вкладку Actions → Eval → Run workflow.

**Ограничения оценки:** набор небольшой и синтетический, результаты показывают тенденцию, а не точные показатели на реальной базе. Ответы GigaChat могут слегка отличаться между запусками.

## 5. Хранение и обработка данных

Для хранения используется **Firebase Firestore**.

| Коллекция | Содержимое |
|---|---|
| `projects` | Проекты режиссёров, контакты и результаты AI-анализа |
| `campaigns` | Заявки на продвижение фильмов |
| `saved_projects` | Сохранённые продюсерами проекты |

**Обработка файлов.** Поддерживаются PDF, DOCX и TXT, максимальный размер 15 МБ. Перед обработкой проверяются расширение, наличие содержимого и размер. Извлечённый текст добавляется к описанию проекта для AI-анализа. PDF, состоящие только из сканов, не обрабатываются.

## 6. Надёжность и безопасность

- Ключи GigaChat и параметры Firebase хранятся в Secrets, а не в исходном коде.
- Панель «Команда» (контакты авторов и заявки) защищена паролем, который задаётся в Secrets (`ADMIN_PASSWORD`). Без настроенного пароля панель закрыта.
- При отсутствии AI-ключа приложение может сохранить проект без AI-анализа.
- Ошибки AI-запросов и обработки файлов перехватываются и показываются пользователю; ключ в тексте ошибок скрывается.
- Пользовательский текст экранируется перед вставкой в HTML.
- Тексты проектов передаются в промпт как данные, а не как инструкции.
- Загружаемые файлы ограничены разрешёнными форматами и размером.
- Проверка SSL-сертификата GigaChat по умолчанию отключена (`GIGACHAT_VERIFY_SSL=false`), так как корневой сертификат НУЦ Минцифры отсутствует в стандартных хранилищах. Для промышленной эксплуатации нужно установить сертификат и включить проверку (`GIGACHAT_VERIFY_SSL=true`).
- Автотесты (`python -m pytest -q`) проверяют разбор JSON, отклонение неполных и выдуманных AI-ответов, сортировку и ограничение оценок, поведение без ключа. Запускаются автоматически в GitHub Actions.

## 7. Известные ограничения прототипа

- Нет авторизации пользователей: роль «продюсер» определяется введённым идентификатором, доступ к панели команды защищён общим паролем.
- Все проекты передаются в ИИ одним запросом. При росте базы потребуется предварительный отбор кандидатов (например, по жанру и формату) и разбиение на части.
- Правила доступа Firestore и защита персональных данных не настроены для промышленной эксплуатации.
- Зависимость от внешних сервисов (GigaChat, Firebase): при их недоступности поиск и сохранение не работают, пользователь видит сообщение об ошибке.
- Качество подбора проверено на небольшом синтетическом наборе, не на реальной базе проектов.

**Шаги до пилота:** авторизация и роли, правила Firestore, отбор кандидатов перед ИИ, лимиты и мониторинг запросов к GigaChat, проверка на реальных профилях режиссёров, включение проверки SSL.

## 8. Запуск проекта

**1. Клонирование**

```bash
git clone https://github.com/DaRvinU/nmh-kinoburo.git
cd nmh-kinoburo
```

**2. Установка зависимостей**

```bash
pip install -r requirements.txt
```

**3. Настройка секретов.** Для локального запуска создайте файл `.streamlit/secrets.toml`. Строки без заголовка должны стоять до блока `[firebase]`:

```toml
GIGACHAT_CREDENTIALS = "ваши_учётные_данные_GigaChat"
ADMIN_PASSWORD = "пароль_для_панели_команды"

[firebase]
# поля сервисного аккаунта Firebase
```

Файл с секретами нельзя публиковать в GitHub (он добавлен в `.gitignore`). Для запуска оценки качества нужен файл `.env` с `GIGACHAT_CREDENTIALS=...`.

**4. Запуск**

```bash
streamlit run app.py
```

**5. Тесты**

```bash
python -m pytest -q
```

**Доступы для проверки.** Для повторения основного сценария нужны ключ GigaChat и настройки Firebase; пароль панели команды и доступы переданы организаторам хакатона. Сценарий: «Авторам» — подать проект; «Продюсерам» — найти его по смыслу; запрос без подходящих проектов должен вернуть сообщение «Подходящих проектов не найдено».

## 9. Развёртывание

Приложение развёрнуто на Streamlit Community Cloud: репозиторий, ветка `main`, главный файл `app.py`. Секреты (`GIGACHAT_CREDENTIALS`, `ADMIN_PASSWORD`, блок `[firebase]`) задаются в настройках приложения. Зависимости устанавливаются из `requirements.txt`.

**Статус проекта:** работающий MVP с AI-анализом кинопроектов, интеллектуальным поиском с порогом релевантности, облачным хранением заявок, панелью команды под паролем, автотестами и воспроизводимой оценкой качества.
